# Bounded CAL automation

Use fresh setup and explicit supervision for physical CAL. A completed run verifies the operation for its recorded meter, sensor, host, and adapter. Normal logging does not start CAL automatically.

## Manual and actual sensor factor

The publisher operating manual was visually reviewed at [CAL description/entry, printed 3-46–47/PDF 76–77](../../references/manuals/hp-437b/HP-437B-Operating-Manual-00437-90047.pdf#page=76), [remote example, 3-48/PDF 78](../../references/manuals/hp-437b/HP-437B-Operating-Manual-00437-90047.pdf#page=78), and [comments, 3-49–50/PDF 79–80](../../references/manuals/hp-437b/HP-437B-Operating-Manual-00437-90047.pdf#page=79). It specifies `CL<REF CAL FACTOR>EN`, 50.0–120.0%, prior zeroing, completion bit 1/value 2 and error bit 3/value 8, and a ten-second example timeout. Incoming program commands abort unfinished CAL; only native serial polls are used while pending. CAL changes gain and retains its entered reference factor; it does not update the sensor data table. It ignores offset/REL/duty during calibration, autoranges, and restores the previous range.

CAL automatically enables the meter's 50 MHz POWER REF oscillator during its routine and restores its prior on/off state afterward. This selected profile requires the initial state **off** and verifies off after known completion. The sensor RF input must be directly on POWER REF, its cable connected to SENSOR, and the existing ZERO still applicable to the same warmed-up setup. There is no OC1/OC0 command, source-on logging phase, repeated ZERO, or manual reference toggle in this case.

The supplied [sensor certificate, page 2](../../references/calibration/hp-8482a/MY41094127/2026-10-15/originals/HP-8482A-SN-MY41094127-Calibration-2026-10-15.pdf#page=2), was rendered and visually inspected: SN **MY41094127**, reference C.F. **99%**, with the 50 MHz table entry **99.0%**. This agrees with the owner's earlier sensor-label report. The prepared current-sensor run therefore uses **99%**, not the displayed measurement CAL FAC of 100.0%. The software requires an explicit factor and source; it has no guessed/default reference factor. The existing CL encoder enforces its exact range/grid and preserves valid numeric spelling (`99` and `99.0` are both valid); no encoder change is made.

## Fixed bounded runner

Selection: **`--supervised-cal --confirm-cal`**, mutually exclusive with other experiments and passive latch reads. Setup requires the existing fresh supervised/prior-worker-stop preparation, plus true `direct_reference_path`, `warmed_up`, and `zero_ready` assertions, an explicit `cal_reference_factor`, and a nonempty `cal_factor_source`. The normal logger does not call this profile. CAL gain changes are explicitly confirmed before opening.

The same thirteen-row plan is used: initial source-off/idle SM and zero ESE/SRE masks; consume old adapter cache; CS and clear native baseline; **one CL99EN** for the recorded sensor; native polling until new completion; post-completion CS and clear native status; source-off/error-free SM; one ordinary acquisition and final SM; normal TR3/GTL/raw closure. No ASCII program command is sent while CAL is pending. No claim about the source being on is inferred from an in-flight SM query; the internal source behavior comes from the manual, with final restoration observed afterward.

The physical work/total budgets are **55/60 seconds**. CAL starts only if the full 30-second completion window and an 18-second finish reserve are available. The follow-up read requires its full 10-second window plus six seconds for final status and cleanup. Writes, other queries, native polling, and local return have a two-second native-call cap. The runner spaces incomplete polls half a second apart and uses up to 60 completion polls, plus cache, baseline, and post-clear polls. It uses distinct tags without wraparound, retains partial poll evidence, and holds a shared resource lease through transport closure.

Before the CL write, the assessment conservatively marks CAL and its reference output as potentially active, because even a partial write can take effect. While CAL completion is unknown, native/framing/partial/cancelled/deadline failures stop **all** later commands, including CS, status queries, local-return commands, and source-off writes that could abort a still-running calibration. Raw close/disposal is permitted. No retry, reconnect, reset, compensating CAL, or automatic gain rollback is performed.

After known completion, a successful timely SM must verify normal/error-free/reference-off state and preserved interpretation flags before `reference_restored_off_verified` becomes true. A missing/late SM keeps reference state conservative in the parent receipt. CAL leaving POWER REF on is an unsuccessful restoration observation, not a pass or an instruction to conceal it with an extra source-off write. Final live/local/reference-off state remains separately owner-observed. Machine qualification flags are not a new test gate; this selected case is decided by its bench/owner record, as with ZERO.
