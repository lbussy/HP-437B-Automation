# Automatic return to local

This document describes the implemented software path and its current operating limits. Hardware behavior on meter SN 3125U22346 remains unverified; use fresh setup and explicit supervision for selected physical work. Normal logging does not start these diagnostic operations automatically.

## Source-backed route

The pinned [PyVISA-py release](https://github.com/pyvisa/pyvisa-py/releases/tag/0.8.1) is 0.8.1. Its USB session does not expose working VISA gpib_control_ren or USB control transfers. Its [USBTMC implementation](https://github.com/pyvisa/pyvisa-py/blob/0.8.1/pyvisa_py/protocols/usbtmc.py) defines GET_CAPABILITIES/GO_TO_LOCAL and the advertised capability bit, and already uses the claimed PyUSB handle for automatic REN. The project extension reuses that same version-pinned session/interface rather than opening another USB handle or modifying installed packages.

The adapter [firmware source at inspected commit 88a1383](https://github.com/xyphro/UsbGpib/blob/88a13830eea3e2d8bf9f6e33123cc1523f42c70a/SW/TestAndMeasurement/TestAndMeasurement.c), control requests near lines 942–949 and main-loop handling near 1222–1236, accepts GO_TO_LOCAL and queues GPIB GTL until transfers finish. A successful control status acknowledges acceptance, not electrical or front-panel proof. The [meter manual, printed 3-35/PDF 65](../../references/manuals/hp-437b/HP-437B-Operating-Manual-00437-90047.pdf#page=65), specifies GTL returning front-panel control with settings preserved; [triggering, PDF 133–134](../../references/manuals/hp-437b/HP-437B-Operating-Manual-00437-90047.pdf#page=133) specifies local returns triggered operation to free-run. GTL is distinct from REN deassertion and clearing lockout.

## Implementation contract

`usb488.py` is original project code for profile `xyphro-usb488-gtl-v1`. It accepts only vendor/product `03eb:2065` and a USBTMC interface class/subclass/protocol FE/03/01, reads the actual interface number, validates the exact 24-byte capability reply/status and USB488 bit 1, and exposes conditional local return after successful negotiation. At shutdown it rechecks support and sends class/interface IN GO_TO_LOCAL (`bmRequestType=0xA1`, `bRequest=0xA1`, wValue 0, actual interface, length 1), requiring exactly `01` back. The pinned dependency gate remains unchanged. Other adapters without the profile retain manual local restoration.

A healthy `Instrument.close()` sends TR3 once, then requests local before closing USB, sharing one operation deadline and worker-process bound. The explicit free-run step corrects the later TRIGGER HOLD finding described below. Close is idempotent and resource close still runs if GTL fails. Explicit `bus("G008")` uses the same negotiated operation; all other bus guards remain. Driver uncertainty after failed parsing/transfers/cancellation suppresses automatic local return; it is not used to recover or abort pending work. Logger metadata records accepted/failed local-return evidence after cleanup, and failed local cleanup makes the session failed rather than completed. The method changes neither POWER REF state nor measurement corrections and does not issue reset, zero, calibration, lockout, clear, retry, or REN deassertion.
